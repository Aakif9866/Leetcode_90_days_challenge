## 👋 Why This Challenge?

This repository is my commitment to spending the next 90 days revising DSA and becoming a better problem solver.

The objective isn't simply to increase the number of problems solved. It's to revisit fundamental concepts, recognize patterns, understand different approaches, learn from mistakes, and become more confident when approaching unfamiliar problems.

I'm using this challenge as an opportunity to strengthen my foundations through consistent, hands-on practice.

**The plan is simple:**

- 🎯 Solve **2–3 LeetCode problems every day**.
- 💻 Write every solution in **C++**.
- 🧠 Understand the approach, not just the accepted answer.
- 🔍 Review mistakes, edge cases, time complexity, and space complexity.
- 📝 Maintain a daily record of problems solved and lessons learned.
- 📈 Track progress through GitHub commits throughout the challenge.

No shortcuts. No chasing streaks without understanding. Just consistent effort and measurable improvement.

|  #  | Problem                                                                                     | Key Concepts                        | Status |

The goal is to revisit these concepts until the underlying patterns become intuitive, rather than merely remembering individual solutions.

## 🚀 Day 02 — Hashing & Two Pointers

**Date:** October 10, 2026

![Hashing](https://img.shields.io/badge/-Hashing-E91E63?style=flat-square)
![Sorting](https://img.shields.io/badge/-Sorting-FF9800?style=flat-square)
![Two Pointers](https://img.shields.io/badge/-Two_Pointers-4CAF50?style=flat-square)

Covered anagram checking, the classic hash-map two-sum pattern, grouping by a canonical key, and 3Sum — including rewriting a brute-force attempt into an optimal two-pointer solution.

|  #  | Problem                                                                | Key Concepts                      | Status |
| :-: | :---------------------------------------------------------------------- | :--------------------------------- | :----: |
| 01  | [Valid Anagram](https://leetcode.com/problems/valid-anagram/)           | Sorting, String Comparison         |   ✅   |
| 02  | [Two Sum](https://leetcode.com/problems/two-sum/)                       | Hash Maps                          |   ✅   |
| 03  | [Group Anagrams](https://leetcode.com/problems/group-anagrams/)         | Sorting as a Canonical Key, Maps   |   ✅   |
| 04  | [3Sum](https://leetcode.com/problems/3sum/) *(extra)*                   | Sorting, Two Pointers              |   ✅   |

### Key Takeaways

- **Valid Anagram:** Sorting both strings and comparing them is a quick way to check for an anagram; a frequency-count approach is a faster alternative worth trying next.
- **Two Sum:** A single pass with a hash map (value → index) replaces the O(n²) brute force.
- **Group Anagrams:** Sorting each string gives a canonical key — the same idea as Valid Anagram, extended to grouping.
- **3Sum:** The brute-force triple loop TLE'd on larger inputs. Rewriting it with sort + fix one index + two pointers brought it down to O(n²).

See [Day-02/notes.md](./Day-02/notes.md) for the full breakdown.

Covered finding the longest run of consecutive numbers using a set, and finding the k most frequent elements using a hash map paired with a max-heap.

|  #  | Problem                                                                              | Key Concepts                 | Status |
| :-: | :------------------------------------------------------------------------------------ | :---------------------------- | :----: |
| 01  | [Longest Consecutive Sequence](https://leetcode.com/problems/longest-consecutive-sequence/) | Hash Sets                     |   ✅   |

### Key Takeaways

- **Longest Consecutive Sequence:** A first DP attempt didn't pan out; the working approach only starts counting a streak from numbers with no predecessor in the set, then walks forward while the next consecutive value exists.

## 🚀 Day 04 — Prefix Sums

**Date:** 13 October 2026

![Prefix Sum](https://img.shields.io/badge/-Prefix_Sum-FF9800?style=flat-square)
![Hash Map](https://img.shields.io/badge/-Hash_Map-E91E63?style=flat-square)

A single problem today, but a pattern-correcting one: a first attempt at a sliding-window solution broke on negative numbers, leading to the prefix-sum + hash-map technique instead.

|  #  | Problem                                                                       | Key Concepts            | Status |
| :-: | :------------------------------------------------------------------------------ | :------------------------ | :----: |
| 01  | [Subarray Sum Equals K](https://leetcode.com/problems/subarray-sum-equals-k/)  | Prefix Sums, Hash Maps   |   ✅   |

### Key Takeaways

- **Subarray Sum Equals K:** Sliding window only works when the running sum is monotonic — negative numbers break that assumption. The fix is tracking prefix-sum frequencies in a hash map and, at each index, adding `mp[sum - k]` to the count.

This one is flagged in **[REVISIT.md](./REVISIT.md)** — the solution works but doesn't yet feel fully internalized.

See [Day-04/notes.md](./Day-04/notes.md) for the full breakdown.

|  #  | Problem                                                                                              | Key Concepts            | Status |
| :-: | :---------------------------------------------------------------------------------------------------- | :----------------------- | :----: |
| 01  | [Two Sum II - Input Array Is Sorted](https://leetcode.com/problems/two-sum-ii-input-array-is-sorted/) | Two Pointers, Sorted Array |   ✅   |

### Key Takeaways

- **Two Sum II:** Because the array is sorted, pointers at both ends can move inward — advance `i` when the sum is too small, retreat `j` when it's too big. O(n) time, O(1) space, no hash map needed.
- **Valid Palindrome:** Build a cleaned lowercase alphanumeric string, then compare from both ends. O(n) time, O(n) space for the cleaned copy.

## 🧠 How I Approach Each Problem

My intended workflow for every problem is:

1. **Understand** — Read the problem carefully and identify constraints and edge cases.
2. **Attempt** — Develop a solution independently before looking for alternatives.
3. **Implement** — Write a clean C++ solution.
4. **Analyze** — Evaluate time and space complexity.
5. **Review** — Identify mistakes, missed edge cases, or a more efficient approach.
6. **Record** — Document the key takeaway in the day's notes.
7. **Revisit** — Return to important problems when revising the relevant pattern.

An accepted submission is a milestone, but understanding _why it works_ is the real objective.
